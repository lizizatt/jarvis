## Plan: Jarvis Mobile Developer Control

Build a TypeScript laptop-resident control plane and installable React PWA, reachable only over Tailscale. Jarvis explicitly registers local checkouts, launches and supervises one GitHub Copilot CLI task per checkout, persists task/transcript/terminal history under `~/.jarvis`, and exposes phone-first task, terminal, git/PR, notification, and preview workflows. The first implementation must verify Copilot CLI's actual machine-readable and session-resume capabilities before cementing its adapter contract.

**Steps**
1. **Validate the runtime contract.** Create a short capability-spike script under `/home/liz.izatt/jarvis/tools/` that, using the existing authenticated GitHub CLI/Copilot CLI account, documents supported non-interactive launch arguments, stdin message delivery, structured or stream output, permission prompts, native session identifiers/resume behavior, exit states, and the command required to resume after interruption. Use a disposable checkout and redact credentials. *Blocks steps 4-6.*
2. **Scaffold the product and local runtime.** Set up a TypeScript workspace in `/home/liz.izatt/jarvis` with `/home/liz.izatt/jarvis/apps/server` for the Node.js service and `/home/liz.izatt/jarvis/apps/web` for the React PWA. Keep transport-specific types next to their consumers so the implemented API remains the source of truth. Add consistent linting, formatting, unit-test tooling, production build scripts, and a local development launcher. *Can begin alongside step 1; agent integration waits on step 1.*
3. **Define durable state and repo registration.** Implement a local SQLite-backed store rooted at `~/.jarvis`, with migrations and backup-safe startup. Model registered checkouts (display name, absolute path, default branch, default agent instructions), task records, task messages/events, native Copilot session metadata, terminal session metadata, notifications, and preview settings. Validate checkout paths and identity at registration; never scan all of `$HOME` or modify a repository. Expose CRUD APIs and a phone-optimized registry/status screen.
4. **Build laptop observation and git/PR services.** Add a repo-state worker that reports branch, dirty status, ahead/behind, recent commits, active task, and per-checkout activity. Implement read-only status/diff endpoints via fixed-argument child processes or a Git library; use the GitHub CLI/API to attach PR/check status and links. Watch registered checkout metadata and publish deltas through authenticated WebSockets.
5. **Implement the Copilot CLI adapter and task state machine.** Wrap the runtime contract verified in step 1 behind an adapter interface. Enforce one active task per registered checkout; launch it in the selected checkout with its default instructions and the user’s initial prompt; persist task messages and stream stdout, stderr, tool/command activity, lifecycle changes, and questions to every connected client in real time through ordered WebSocket events. Support chat-style follow-up messages and native-session resume where available. Give every running agent an always-visible stop action backed by an idempotent cancellation transition: stop accepting input, terminate the entire agent process group and spawned children, record who stopped it and when, release the checkout slot only after termination is confirmed, and retain the transcript as `stopped`. Detect questions/approval events using structured signals where available, with an explicit documented fallback if only terminal text is available. On server/laptop restart, mark active tasks interrupted and offer manual resume/restart rather than claiming continuity.
6. **Add policy, consent, and audit behavior.** Create a globally configurable policy passed to the CLI adapter and displayed in the task UI. It should permit the intended autonomous developer workflow but inject the rule that agents must ask the user before commit/push/PR operations unless the user explicitly grants permission in the task. Do not add a Jarvis-side git landing gate. Persist task inputs, approval/answer messages, lifecycle events, and command metadata indefinitely; do not capture or display credentials.
7. **Provide reconnectable full-shell terminals.** Run named, persistent per-checkout PTY sessions under the laptop user (prefer a maintained terminal multiplexer such as `tmux` for process survival) and bridge them through the authenticated WebSocket service. Let the PWA reattach after refresh or network loss, create/select a checkout terminal, resize it, and clearly distinguish it from an agent task transcript. Full shell authority is intentional; bind the server to Tailscale/private interfaces only.
8. **Build the PWA workflows.** Implement an installable, responsive React PWA with a repository overview showing registered checkouts, branch/dirty state, current task activity, elapsed time, latest agent action, and a primary entry to start/select a task. Implement a checkout view with an incrementally rendered live event timeline, task transcript/chat input, question/approval state, current command/tool indication, terminal tab, branch and diff views, plus PR/check summary. Keep an always-visible per-agent stop button while the task is starting or running, immediately show `stopping`, prevent duplicate cancellation, and settle to `stopped` only after server confirmation. Render reliable completed, failed, stopped, and interrupted states plus persistent historical tasks, with native Copilot session identifiers surfaced only when available.
9. **Deliver notifications.** Register standard Web Push subscriptions from the installed PWA and store them locally. Emit notifications for agent questions, task completion (including failure/interruption), and push/PR completion detected from agent events or repository/PR refresh. Tapping a notification must route to the relevant task/check-out view.
10. **Add Jarvis-owned preview routing.** Manage a Jarvis landing document at `~/.jarvis/<registered-repo-id>/index.html`, without changing the corresponding checkout or `.gitignore`. Serve that entry and a read-only, path-contained route for files within its registered checkout, so landing HTML can link to other repository HTML files. Require the same authenticated Jarvis origin; block traversal, symlink escapes, and cross-repository reads. Defer custom preview-to-backend APIs and dev-server proxying until the core remote agent workflow is stable.
11. **Package and operate the service.** Add a per-user systemd unit under `/home/liz.izatt/jarvis/deploy/systemd/` that starts after the Tailscale network is usable and restarts the server on failure. Provide installation/upgrade documentation, config locations, data backup/restore guidance, and an explicit laptop-only setup step that verifies `gh`/Copilot CLI authentication. Configure reverse-proxy/TLS only if the chosen Tailnet deployment requires it; do not expose a public endpoint.

**Relevant files**
- `/home/liz.izatt/jarvis/apps/server/` — Node.js HTTP/WebSocket service, SQLite persistence, GitHub/Copilot CLI adapters, repo watcher, terminal bridge, preview server, and Web Push sender.
- `/home/liz.izatt/jarvis/apps/web/` — responsive React PWA pages for repository inventory, task chat/transcript, terminal, diffs, PR status, previews, and notification subscription.
- `/home/liz.izatt/jarvis/tools/` — Copilot CLI capability probe and local developer scripts.
- `/home/liz.izatt/jarvis/deploy/systemd/` — per-user systemd service template and installation helper.
- `~/.jarvis/` — runtime-owned SQLite database, configuration, task/transcript retention, notification subscriptions, and per-repository managed preview landing pages; never committed into registered repositories.

**Verification**
1. Run the capability spike against the authenticated installed Copilot CLI and record the supported adapter behavior, with no token or secret in output.
2. Unit-test persistence migrations, checkout registration/path validation, task state transitions, policy prompt construction, stream/event parsing, restart interruption, and preview path containment including symlink escape attempts.
3. Integration-test two registered copies of a test repository: start one task in each, verify ordered real-time output and activity updates on two connected clients, reject a second task in the same checkout, send a follow-up message, stop one agent while it has a spawned child process, confirm the full process tree exits and the checkout slot is released, then restart the server and manually resume the other interrupted task.
4. Exercise a persistent terminal through a simulated reconnect and confirm commands continue under the intended laptop user and selected checkout.
5. Validate Git status/diff and GitHub PR/check state against a fixture repository; ensure all Git subprocess invocations use fixed arguments and no arbitrary shell interpolation.
6. Use Playwright at phone-sized and desktop viewports to verify the PWA install flow, live updates, task question flow, terminal layout, diff readability, notification routing, and preview links into repository HTML.
7. Test access from a Tailnet-connected phone/device and verify non-Tailnet/public-network requests cannot reach the service; verify systemd restart and local history durability.

**Decisions**
- Included MVP: explicit checkout registry; one Copilot CLI task per checkout; native-session mapping where available; chat-first task interaction; full reconnectable user-shell terminal; Git/diff/PR status; PWA web push; read-only repo HTML previews; systemd operation.
- Excluded MVP: reading/copied conversation history from the Copilot App, automatic worktree creation or checkout scheduling, mobile file editing, transcript full-text search, direct public Internet exposure, preview-specific backend APIs, and repository dev-server proxying.
- Trust boundary: Tailscale identity authenticates the user. The app intentionally exposes the laptop user’s full shell and trusted registered-repo HTML; credentials remain in existing GitHub CLI/Copilot CLI storage and are never copied into Jarvis state.
- Landing behavior: Jarvis owns `~/.jarvis/<registered-repo-id>/index.html`; it may link to the same registered checkout through a read-only, contained server route. No repository setup file is required.

**Further Considerations**
1. The capability spike is a real dependency, not ceremony: if Copilot CLI lacks a supported native session-resume or structured event interface, Jarvis should provide durable task transcripts and manual re-launch with summarized context, while making the reduced fidelity explicit.
2. Full-shell access plus Tailnet-only authentication is an intentional convenience/security trade. Add a second factor or device revocation workflow later if phone loss is a realistic concern.
3. Thumbnail support can be added once usage shows value, as an optional `~/.jarvis/<registered-repo-id>/thumbnail.*` asset rather than a repository convention.
